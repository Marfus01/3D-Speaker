# HMM 建模及实现优化记录

## audio hmm（人脸存在情况固定，认为无误差）
在引入人脸存在情况和active speaker face信息作为隐藏状态初始、转移概率的协变量之后，当前模型在不加任何约束时，已经能达到较好的效果，但acc仍低于g观测序列（详细结果参见过程记录/2.hmmx_v2.md）。此外，在我爱我家数据集上，单次M步需要半小时左右。因此，计划从统计建模和计算效率两个方面进行优化。
> 代码位于3D-Speaker/speakerlab/process/hmm/hmm_X.py。

### 统计建模优化
#### 混淆矩阵引入语音时长信息作为协变量
将语音时长整体做预处理（如标准化/归一化/...）之后，作为协变量引入到混淆矩阵对角线元素的计算中，从而根据时长动态调整混淆矩阵。
注意到，观察根据时长分组后，在各组标注数据上测试出来的acc，group0, group1, group2-4的acc有明显差异。
考虑到，acc随时长增加的变化并非线性/指数的，而且时长>2s的组acc接近，直接将时长作为连续变量通过逻辑回归引入混淆矩阵可能并不合适。
更好的做法是，与分析结果时的方式相同，将时长离散化为5组，将组别作为类别变量引入混淆矩阵的计算中。
> 具体而言，假设时长分组变量为L，有5个取值，则对于说话人混淆矩阵，有：
> ```math
> P(s_obs=j | s_true=i, L_class=c) \propto exp( B_s_{i,j} + \sum_{m=1}^{4} l_m * I(L_class=m) * I(i=j)) )
> ```
> 其中，B_s为基础混淆矩阵的logits，l_m为时长组m对应的偏置参数，I(.)为指示函数。
注意到，各组包含的样本数不均衡，具体情况为：(array([0, 1, 2, 3, 4]), array([ 406, 3067, 2346,  813,  197]))。后续可能可以考虑对这些样本再做一些拆分/合并。


#### 将hidden states的转移从一阶Markov链扩展到二阶Markov链
最直观的想法是把更前一时刻的hidden states也作为协变量引入初始、转移概率的计算中。但这样做会对统计模型带来较大的改变，E步计算的forward、backward算法复杂度会明显提升，且递推公式也会有所变化。暂时不考虑。

### 计算效率提升
目前计算效率的瓶颈主要在无解析解的M步数值优化。在audio hmm中，可以每个M步随机选择部分数据，进行类似mini-batch的优化，从而提升计算效率。
> 在完整模型中，E步的计算复杂度也较高。除了下面提到的候选子集方法外，还可以考虑使用SMC 抽path做近似计算。这也能够避免遍历计算所有隐藏状态组合的概率。但这样做的一个问题是，与viterbi解码存在一定程度的不一致。

### 微调数据筛选
筛选数据时，既可以按照embedding cos-sim的阈值进行筛选，也可以按照hmm解码结果的后验概率筛选。但从目前的结果来看，后者可能不具备明显优势。




## 完整模型
### 计算效率提升
#### gpu版本
目前已经在hmmlearn项目下实现了一版，但是计算结果与cpu版本不一致，仍需调试。
由于在程序相同的情况下，gpu版本相较cpu版本计算速度的提升空间有限，这一优化的优先级较低。

#### 函数实现优化
1. 在开发nested_hmm_x的gpu版本时，发现了一些可以通过广播机制提升cpu版本效率的方式。目前已经迁移到了nested_hmm_x的cpu中。✅
2. 在测试人脸存在情况固定的audio-only hmm时，发现M步可以仅筛选权重非零的取值组合做forward计算，这有助于缩短计算时间。（NOTE: 目前尚未迁移到完整模型）

#### 降低计算复杂度的思路：仅考虑候选子集
cpu上，目前观察到EM算法计算的主要瓶颈在前向，反向算法中，U,V统计量的更新环节。例如，在前向过程中，计算时间主要花费在以下两个环节：
1. 目前在每一个时刻t，log_probs_arr 的计算通过广播机制实现，需要计算若干个形状为(2^n, n, 2^n, n)的4维张量的和；
2. 目前在每一个时刻t，为了获取U统计量，需要对 log_probs_arr 的前两个维度做 log_sum_exp 操作。
经过讨论，目前的解决思路是缩小需要计算的face hidden states的集合。具体而言：
##### 候选子集定义✅
给定t时刻人脸存在状态的观测，定义一个所有人脸存在情况集合的依赖于观测的子集，其余情况均认为后验概率为0。子集的具体定义方式有若干种。例如：
1. 利用embedding cos-sim的信息：对于当前帧的每一张人脸，认为与其余弦相似度最高的top-k个 avd 簇，均有可能是其真实标签；
2. 仅利用人脸存在向量的信息：将0-1 encoding首先转化为簇id的集合，在2^n种可能情况中，筛选对应集合与观测集合重叠度（例如，通过IOU衡量）较高的部分。
> 方法2的一个局限性是，当人脸存在向量全0/只有1个1时，IOU指标的阈值难以处理。而且在当前帧没有人脸时，hidden states也有可能解码出人脸出现情况。

经过权衡，选择方法1作为最终方案。注意到，这与原来人脸观测标签的获取方式形成了巧妙的互补：
- 原来中间帧人脸聚类簇与avd聚类簇的对齐是cluster-cluster的对齐，虽然能在整体上保证acc，但在局部难免存在偏差；
- 而方法 1 采用的是sample-cluster的对齐，能够兼顾细粒度的相似度。
> 之所以没有使用sample-sample的对齐，是因为top-k个最相似的样本不一定来自不同的簇，难以保证多样性。除非使用while循环，不断扩展候选集合，直到包含k个不同的簇为止，但这样会增加计算复杂度。

为了保证候选子集的id与avd聚类簇，speaker聚类簇都是对齐的，需要在前期已经将三种聚类簇对齐之后，再对剩余的这些关键帧人脸提取候选alignment id set 信息。
target cluster，既可以使用处理后剩余的vad cluster，也可以使用处理后剩余的关键帧cluster。
> 目前暂时使用后者，因为更直接，sample与target cluster的样本也更接近。

##### HMM 人脸修改✅
1. 将根据face states是否存在于子集中定义的随机变量作为X_f, 影响初始概率和转移概率的计算（主要影响的是归一化步骤）
> 由此构建的人脸转移概率约束效果可能与混淆矩阵约束类似，但在数学上更合理，同时有助于减少计算量
2. U, V统计量的计算中，仍将两者初始化为形状为(T, 2^n, n)，取值均为-inf（对应概率为0）的张量。以U统计量为例
a. t=0: 根据当前时刻的X_f，仅对X_f(f_state)=1的f idxs计算U统计量取值，然后选中U(0, :,:)中这些f idxs对应的部分赋值
b.1. t>0: 根据前一时刻和当前时刻的X_f，从各个4维张量中选择形状为形状为(n_f_potential_t-1, n, n_f_potential_t, n)，计算它们的和，并对前两个维度直接做logsumexp，将结果赋值给(0, :,:)对应的部分
> 之所以可以对第一维直接做，是因为其他元素exp(*)=0，求和为0，不影响U统计量更新
c. 发射概率计算上，也仅筛选出 X_f(f_state)=1 的 f idxs对应的部分。就U,V统计量更新而言，这等价于认为 X_f(f_state)=0 的 f_state 对应的观测概率为0。
d. 相应修改M步、后验概率计算和维特比解码。

做以上修改之后，E步的计算复杂度大幅降低，但是M步人脸初始、转移概率的M步变复杂。尤其是后者，需要使用LBFGS优化器求解，成为了计算上的主要瓶颈。

##### HMM 语音修改
与人脸部分类似，需要在前向、后向算法中，根据语音隐状态是否存在于候选子集中，调整初始概率、转移概率的计算。
